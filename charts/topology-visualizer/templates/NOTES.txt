{{ include "topology.fullname" . }} installed into namespace {{ .Release.Namespace }}.

Cluster ID: {{ .Values.clusterId }}
  This value is embedded in every node ID and MUST match on the agent and the backend.
  It is templated from one chart value, so it cannot drift unless you override it twice.

1. Wait for readiness:

     kubectl -n {{ .Release.Namespace }} rollout status ds/{{ include "topology.fullname" . }}-agent
     kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "topology.fullname" . }}-backend

2. Confirm an agent pod is running on EVERY node (control-plane included):

     kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/component=agent -o wide

3. Open the UI (port-forwarding is the default access method for kind):

     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "topology.fullname" . }}-frontend {{ .Values.frontend.service.port }}:{{ .Values.frontend.service.port }}
     open http://localhost:{{ .Values.frontend.service.port }}

4. Query the graph directly:

     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "topology.backendService" . }} {{ .Values.backend.service.port }}:{{ .Values.backend.service.port }}
     curl -s 'http://localhost:{{ .Values.backend.service.port }}/api/v1/graph?window=5m' | jq

An empty graph is the normal first state. Generate traffic and allow up to 20 seconds:
agent aggregation is {{ .Values.agent.flushIntervalSeconds }}s, plus a 5s UI poll.
