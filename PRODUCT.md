# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Two audiences, held equally, per the user's confirmation:

- **Platform/SRE engineers** operating a real Kubernetes cluster, who need to see which workloads actually talk to each other at runtime — not what manifests declare.
- **FYP evaluators** (supervisor/examiners) assessing the project through the `kind` demo walkthrough and the written report.

Design and build decisions should hold up as a genuine operational tool while also landing cleanly in a live, time-boxed demonstration. Neither audience should be sacrificed for the other.

## Product Purpose

Shows which Kubernetes workloads actually communicate, by observing TCP connection establishment in the kernel with eBPF — not by reading manifests, and without modifying, instrumenting, or injecting anything into the observed applications. A manifest tells you what was declared; this tells you what happened.

Success means: install onto a cluster, capture real traffic, and see an accurate, understandable dependency graph — including relationships nothing in the manifests predicted.

## Positioning

Runtime observation instead of static inference. The alternatives considered and rejected (ADR-001 §11) sharpen the claim: inferring topology from manifests only shows possible relationships, not observed ones; a service mesh proves the same thing but requires sidecars and changes the environment being measured; packet capture goes further than needed and raises privacy/complexity cost. This tool's position is the low-instrumentation middle: L3/L4 metadata only, one privileged agent, no application changes.

## Operating Context

- Installed as a Helm chart into a Kubernetes cluster (`kind` for demo/dev, validated separately on multi-node kubeadm).
- Driven through `make` targets: `demo-up`, `demo-traffic`, `demo-verify`, `demo-down`, etc.
- Frontend reached via `kubectl port-forward`; no external ingestion or ingress exposure by default.
- Development follows an ADR-driven, phase-gated process (`docs/adr/`, `docs/evaluation/`, phase-gate skill) — architectural changes go through an ADR, not ad hoc.
- The demo script (`docs/demo-script.md`) is a fifteen-minute walkthrough and is itself a real usage scene the UI is judged against.

## Capabilities and Constraints

- IPv4 TCP connection establishment only (active opens); IPv6, UDP, SCTP, ICMP, and Unix sockets are out of scope for this release.
- No payload inspection ever; only L3/L4 metadata.
- Connection counts, not request counts — one pooled connection carrying 10,000 requests counts as 1. This distinction must never be blurred in UI copy.
- Byte volume is deliberately not shown: measured as accurate but only readable at connection close, which would draw the busiest persistent edges as the faintest. Connection count is the traffic-intensity fallback.
- A dependency that did not communicate inside the selected time window does not appear — this is the cost of the property that makes the tool useful, not a bug to hide.
- Default data retention is 60 days (`RETENTION_HOURS`), configurable; purge runs hourly.
- Graph responses cap at 500 nodes / 2,000 edges (backend); the ungrouped UI is unusable past ~300 edges, which is why namespace grouping, expansion, and focus-on-selected-workload exist ahead of a hard 400-edge display cap.
- Comparison mode diffs two arbitrary time periods (not only adjacent windows) into `NEW` / `REMOVED` / `CHANGED`, successful establishments only.
- Individual external IPs are never persisted or displayed; unknown routable destinations collapse into one `EXTERNAL` node.
- Only the eBPF agent runs privileged; backend and frontend run non-root, read-only root filesystem, no extra capabilities.
- Target demo resolution is 1280x720; the UI must stay usable at that size and meet WCAG AA.

## Evidence on Hand

- `docs/limitations.md` — full, numbered accounting of what the system cannot do, each one measured rather than assumed.
- `docs/evaluation/` — raw experiment results and method backing every performance claim (e.g. 35 MiB agent memory, 1,325 events/s capture, 62 ms p95 graph query at 500 nodes/2,000 edges).
- `docs/demo-script.md` — the actual demo walkthrough, reproducible via `make demo-up` / `demo-traffic` / `demo-verify`.
- No real customer deployments, testimonials, or case studies exist, and none should be fabricated — all demo traffic is synthetic, generated by `demo/` workloads under the project's own control.

## Product Principles

1. **Show what happened, not what was declared.** The entire value proposition is runtime truth over manifest inference; nothing in the UI should imply more certainty than was observed.
2. **State limitations honestly instead of hiding them.** Unmeasured, unresolved, and truncated states are shown explicitly (e.g. "unmeasured" timing, unresolved-endpoint counters) rather than smoothed over.
3. **Never fabricate certainty.** Ambiguous Service attribution, unresolved endpoints, and zero-sample timing are preserved as distinct states, not collapsed into a default guess.
4. **Least privilege, visibly.** Only the collector is privileged; that boundary is a stated design commitment, not an implementation detail to obscure.
5. **Serve the operator and the evaluator at once.** Every surface should work as a real diagnostic tool during a live cluster investigation and hold up under a time-boxed demo walkthrough.

## Accessibility & Inclusion

WCAG AA is a stated requirement (ADR-006): keyboard focus, labels, and contrast must meet it, and comparison-mode status (`NEW`/`REMOVED`/`CHANGED`) must be distinguishable without relying on color alone. Node kind must be communicated by shape/icon, not color alone.
